# ELM327 ↔ ESP32-C6 Mini — Design Spec

**Date:** 2026-07-09  
**Status:** Approved for planning  
**Platform:** ESP32-C6 Mini, ESP-IDF  
**OBD adapter:** ELM327 Mini over BLE  

## 1. Goal

Build a production-ready, modular ESP-IDF firmware that:

1. Connects an ESP32-C6 Mini to a BLE ELM327 Mini.
2. Exposes a full AT + OBD command surface behind a hard read-only safety gate.
3. Polls vehicle data via dynamic, switchable profiles.
4. Delivers data through replaceable transports (serial + SoftAP webserver in v1).
5. Keeps OBD/ELM logic independent from how data is sent (fleet UART / Zigbee later).

### Non-goals (v1)

- Zigbee peer transport (interface stub only).
- Fleet-management UART bridge (interface stub only).
- Writing/actuating vehicle systems (Mode 04 clear DTC, Mode 08 control, etc.).
- Full OTA implementation (partition layout + stub API only).

## 2. Constraints & decisions

| Topic | Decision |
|---|---|
| Link to ELM327 | BLE central (ESP32-C6 has no Bluetooth Classic) |
| Command surface | Full AT + OBD, gated by allowlist |
| First transports | USB serial console + SoftAP HTTP |
| BLE binding | Scan → user select → persist → auto-reconnect |
| Polling | Config-driven poller + named profiles |
| Safety | Allowlist-only; Mode 04/08 blocked; unsafe unlock off by default |
| Architecture | Layered ESP-IDF components + transport interface |

## 3. Architecture

Strict layering. OBD/ELM never depends on HTTP, Zigbee, or fleet UART.

```
app_main
  → sys_runtime (WDT, logs, metrics, OTA stub)
  → profile_store / config (NVS)
  → telemetry_bus
  → transports: serial_console, http_softap  (+ later uart_fleet, zigbee)
  → obd_poller + profiles
  → cmd_policy (safety gate)
  → elm327_client
  → elm_transport interface
       ↳ ble_elm (NimBLE) today
  → obd_codec (pure decode)
```

### Component responsibilities

| Component | Responsibility | Depends on |
|---|---|---|
| `ble_elm` | BLE central: scan, connect, disconnect, GATT write/notify; reconnect | NimBLE |
| `elm_transport` | Byte I/O interface: `write`, `read_line` | — |
| `elm327_client` | AT session, single in-flight command, timeouts, response parse | `elm_transport` |
| `cmd_policy` | Allowlist gate before any bytes leave the device | — |
| `obd_codec` | Mode 01 formulas, DTC parse, VIN helpers, capability masks | none (pure C) |
| `profile_store` | Profiles, active profile, BLE bond, SoftAP settings in NVS (JSON) | NVS, cJSON |
| `obd_poller` | Profile schedule + priority raw-command queue | client, codec, policy, store |
| `telemetry_bus` | Typed pub/sub for samples, events, errors | FreeRTOS queues |
| `transport_serial` | Interactive console for scan/select/cmd/profiles/live dump | bus + APIs |
| `transport_http` | SoftAP + REST + simple HTML UI | bus + APIs |
| `sys_runtime` | Task WDT, structured logging, metrics counters, OTA stub | ESP-IDF |

### Key interfaces

```c
typedef struct {
    esp_err_t (*write)(void *ctx, const uint8_t *data, size_t len);
    esp_err_t (*read_line)(void *ctx, char *buf, size_t buflen, uint32_t timeout_ms);
} elm_transport_t;

esp_err_t telemetry_publish(const telemetry_msg_t *msg);
esp_err_t telemetry_subscribe(telemetry_sub_t *sub); /* queue + filter mask */
```

Later transports (fleet UART, Zigbee) subscribe to `telemetry_bus` and/or call the same command APIs; they do not talk to BLE or ELM directly.

## 4. BLE binding

1. User triggers scan via serial or HTTP.
2. Firmware returns discovered devices (name, addr, RSSI).
3. User selects one device.
4. Selection persisted in NVS (address + optional name + GATT UUID overrides).
5. On boot, if bond exists → connect with exponential backoff; else wait for select.

**GATT defaults:** Nordic UART Service (NUS) TX/RX characteristic UUIDs.  
**Overrides:** TX/RX service/characteristic UUIDs configurable in NVS for clone adapters.

## 5. ELM session & data flow

### Boot

1. Init NVS, WDT, logging, metrics.
2. Load config (SoftAP, BLE bond, profiles, active profile, safety flags).
3. Start telemetry bus, SoftAP HTTP, serial console.
4. Connect BLE if bonded; otherwise idle until select.
5. On link up → run ELM init AT sequence from active profile (or defaults).
6. Start poller on active profile.

### Default ELM init

`ATZ`, `ATE0`, `ATL0`, `ATS0`, `ATH0`, `ATSP0` (overridable per profile).

### Concurrency

- Exactly one ELM command in flight (mutex).
- Raw command queue has priority over scheduled poll ticks.
- Telemetry publish is non-blocking; on subscriber overflow drop oldest and increment `telemetry_drops`.

## 6. Profiles & configuration

Profiles stored as JSON in NVS.

```json
{
  "name": "fleet_basic",
  "init_at": ["ATZ", "ATE0", "ATL0", "ATS0", "ATH0", "ATSP0"],
  "items": [
    { "cmd": "010C", "interval_ms": 200,  "decode": "rpm" },
    { "cmd": "010D", "interval_ms": 200,  "decode": "speed" },
    { "cmd": "0105", "interval_ms": 2000, "decode": "coolant_c" },
    { "cmd": "ATRV", "interval_ms": 5000, "decode": "voltage" }
  ]
}
```

- Built-in profiles: `fleet_basic`, `diagnostics` (includes slower PID set + DTC/VIN helper commands).
- CRUD via serial and HTTP.
- Switching profile: stop schedule → optional re-init → start new schedule.
- Profile save rejects any item that fails `cmd_policy`.

## 7. Command safety policy

**Default: allowlist only. Fail closed.**

### Allowed

- Safe AT session/status commands from an explicit enumerated allowlist in `cmd_policy` (not a regex free-for-all). Initial set includes:  
  `ATZ`, `ATD`, `ATWS`, `ATE0`/`ATE1`, `ATL0`/`ATL1`, `ATS0`/`ATS1`, `ATH0`/`ATH1`,  
  `ATSP0`–`ATSP9`, `ATDP`, `ATDPN`, `ATRV`, `ATI`, `AT@1`. Additional AT commands require a code change to the allowlist.
- OBD Mode `01` (live PIDs)
- OBD Mode `02` (freeze frame)
- OBD Mode `03`, `07`, `0A` (read DTCs only)
- OBD Mode `09` (VIN / vehicle info)

### Blocked in v1

- Mode `04` (clear DTCs / readiness impact)
- Mode `08` (bidirectional control / actuation)
- Any command not on the allowlist
- Manufacturer/extended control-looking commands not explicitly allowlisted

### On block

- Do not send bytes to BLE.
- Return `ESP_ERR_NOT_ALLOWED` / HTTP 403.
- Log `cmd_blocked` with command and source (`poller` | `http` | `serial`).
- Increment `blocked_cmds` metric.

### Escape hatch

- NVS flag `safety.allow_unsafe` defaults to `false`.
- Enabling requires explicit admin action via serial/HTTP and emits a loud warning log.
- Even with the flag, Mode `08` remains blocked in v1 unless a future audited unlock is designed.

## 8. Telemetry model

Transports consume typed messages; they do not parse ELM text themselves for live data.

| Type | Payload |
|---|---|
| `pid_sample` | `cmd`, `name`, `raw_hex`, `value`, `unit`, `ts_ms`, `ok` |
| `dtc_list` | codes[], source mode, `ts_ms` |
| `elm_event` | `connected` / `disconnected` / `init_ok` / `init_fail` |
| `error` | typed code, optional cmd, message, `ts_ms` |

## 9. Transports (v1)

### Serial console

- Status, BLE scan/list/select, raw cmd, profile CRUD/activate, live sample dump, metrics.
- Same command APIs as HTTP; safety gate still applies.

### SoftAP HTTP

- SoftAP for phone/laptop join during bring-up.
- REST:
  - `GET /api/status`
  - `POST /api/ble/scan`, `GET /api/ble/devices`, `POST /api/ble/select`
  - `POST /api/elm/cmd` → raw + decoded (if allowlisted)
  - `GET/PUT /api/profiles`, `POST /api/profiles/active`
  - `GET /api/telemetry` (latest snapshot; SSE optional if schedule allows)
  - `GET /api/metrics`
- Simple embedded HTML page: scan/select, live values, raw cmd, profile switch.

### Future transports

- `transport_uart_fleet` and `transport_zigbee` implement the same subscribe/publish pattern; no changes required inside `elm327_client` / `ble_elm`.

## 10. Error handling & resilience

| Condition | Behavior |
|---|---|
| BLE drop | Publish disconnect; stop poller; exponential backoff reconnect to bonded device |
| ELM init fail / `UNABLE TO CONNECT` | Retry init N times; enter `degraded` (HTTP/serial remain up) |
| Command timeout | Default 2–5 s (configurable); mark sample `ok=false`; continue schedule |
| `NO DATA` / bus errors | Typed error + metric; do not crash poller |
| Hung task | Task WDT; SoftAP/console must remain usable |

Typed errors include: `BLE_*`, `ELM_TIMEOUT`, `ELM_NO_DATA`, `ELM_BUS_ERROR`, `CMD_BLOCKED`, `PROFILE_INVALID`.

## 11. Production readiness (v1)

- Task watchdog enabled and fed by heartbeat task.
- Structured logs (component tag + level).
- Metrics: `cmds_ok`, `cmds_fail`, `ble_reconnects`, `blocked_cmds`, `telemetry_drops`, uptime.
- Kconfig for SoftAP defaults, BLE scan/connect timeouts, ELM command timeout, and log level; safe defaults.
- OTA: flash partition layout reserved + stub hook/API; full OTA deferred.
- Host unit tests for `obd_codec` and `cmd_policy`.
- Fake `elm_transport` tests for `elm327_client` / poller scheduling behavior.

## 13. Success criteria (phase 1 done)

1. Scan, select, and persist a BLE ELM327; auto-reconnect after reboot/drop.
2. ELM init succeeds; allowlisted AT/OBD commands work via serial and HTTP.
3. Mode `04` / `08` / unknown commands are blocked and never reach BLE.
4. Active profile polls on schedule; profile switch works without reboot.
5. Telemetry visible on serial and SoftAP web UI/API.
6. Watchdog, metrics, and structured logs are active.
7. Host unit tests cover codec formulas and policy allow/deny decisions.
8. Transport boundary is clear enough that adding Zigbee/UART later does not require rewriting ELM/BLE layers.

## 14. Open implementation notes

- Exact NUS vs vendor UUID probing: try configured UUIDs first; document how to capture UUIDs from a phone nRF Connect session if a clone differs.
- SoftAP SSID/password defaults via Kconfig; changeable at runtime and stored in NVS.
- Mode `05`/`06` not required for v1; treat as denied unless later explicitly allowlisted as read-only.
